## What happened

Routing was verified working, then broke again the moment the re-route guard was
reinstated. The guard used `Routed Timestamp Is Null`, first as a start condition,
then as a decision outcome. Both evaluated false against a genuinely null DateTime.

## Diagnosis

Debug trace rendered the condition as:

    {!$Record.Routed_Timestamp__c} (null) Is null null

Field resolving, correct operator, correct null value, result false. The start
condition engine and the decision engine fail identically.

## Fix

Replaced the null test with a Boolean formula resource `isNotRouted` =
`ISBLANK({!$Record.Routed_Timestamp__c})`, and compared it Equals
`{!$GlobalConstant.True}`. Verified: one routing update, no recursion.

## What it costs

- Four attempts spent on `Is Null`, two of them against the start condition.
- Lesson: when a null comparison misbehaves, convert it to a Boolean formula rather
  than trying other operators. `ISBLANK` is reliable where `Is Null` is not.
- Watch for this on any other DateTime null test in the org.

## Follow-up

Fault connectors added to updFound and updDefault so DML failures surface.
